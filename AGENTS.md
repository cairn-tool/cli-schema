# Working in this repository

## C# code style

**K&R bracing.** The opening brace stays on the declaration line, and `else`, `catch` and
`finally` stay on the line that closes the block before them.

```csharp
public sealed record Arity(
    int Min,
    int? Max);

if (found) {
    Use(found);
} else {
    Fail();
}
```

This is set in [`.editorconfig`](.editorconfig) under `[*.cs]`, with
`dotnet_diagnostic.IDE0055.severity = error`. That severity, plus `EnforceCodeStyleInBuild` and
`TreatWarningsAsErrors` in `dotnet/Directory.Build.props`, means a formatting violation breaks the
build rather than merely showing up in a report.

```bash
npm run format:csharp:check   # dotnet format --verify-no-changes --severity error; CI runs this
npm run format:csharp         # fix it
```

⚠️ **`dotnet format` will not check a generated file.** A `// <auto-generated />` header makes it
skip the file entirely, so a generator emitting the wrong brace style diverges silently — which is
exactly what happened here once. The emitter in
[`scripts/emit-csharp.mjs`](scripts/emit-csharp.mjs) produces K&R deliberately; keep it that way
rather than relying on the formatter to notice.

## Generated code

**Do not hand-edit `packages/cli-schema/src/generated/` or
`dotnet/src/CairnTool.CliSchema/Generated/`.** Both are produced from
[`spec/v1/cli-schema.json`](spec/v1/cli-schema.json); an edit is overwritten by the next run and
rejected by CI.

```bash
npm run codegen        # regenerate both languages
npm run codegen:check  # CI gate
```

What stays hand-written, and why: `CONTRACT_VERSION`, `isRequired` and `isVariadic` are not shapes;
the three leaf unions in `types.ts` are kept because the generated `ValueType` folds `null` into
the union where the published one never has; and `CliSchemaJsonContext` is serialization
_behaviour_ — its options are what make the two languages agree on the wire.

## These packages are published

`@cairn-tool/cli-schema` and `CairnTool.CliSchema` are at 1.0.0 on public registries. **A change to
a generated type is a change to somebody else's compile.** A type that is merely shaped differently
— a class where there was a record, a `List` where there was an `IReadOnlyList`, an init property
where there was a constructor parameter — is still breaking.

The conformance goldens are the instrument for catching it:

```bash
npm run build && npm test
dotnet test dotnet/CliSchema.slnx -c Release
npm run conformance
```

**The gate is that every golden still matches with no `expected.json` edited.** A golden that needs
changing means the wire format moved, which is a bug in the change rather than an intended
outcome. `git diff spec/conformance/` must come back empty.

## The spec

`schemaVersion` is hand-owned and independent of the package versions. No schema sets
`additionalProperties: false`, so adding a property is non-breaking and consumers must ignore what
they do not recognise. Adding a definition is additive; adding a `required` entry is not, and
belongs in `spec/README.md` where a reader will find it.
